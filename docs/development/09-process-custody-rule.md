# Process Custody Rule

Each work-started process has one lifetime owner: task, server generation, delegated run, test session or installation. End or hand it to a longer-lived owner, never init. Verify identity by ledger, `OURO_{INSTALL,TASK}_SCOPE_<hex>=1` or recorded group, never command line. Terminal paths settle, never provision/spawn/admit. Failed reads/signals mean unverified; retire only on recorded settled/no-census outcomes (`test_task_scope_lifetime.py`, `test_exit_does_not_admit.py`).

**Spawn chokepoint.** `Popen`/`mp.Process` without bounded same-call waits use `process_custody.spawn_supervised`; existing managers immediately `record_process`. Scopes: `task|session|daemon`; installation daemons survive generations. Plain `start_parent_lifeline` applies `lifeline_parent_env()` LAST, excluding grandparent identity; multiprocessing uses its parent sentinel (`test_pid1_parent_lifeline.py`). Worker kills use `worker_pool_lifecycle.kill_worker_tree`, sparing `live_daemon_root_pids`; cancel/timeout and idle retirement also keep retained services. Other supervisor `kill_pid_tree` calls are defects. Ledger/fingerprint/companion exceptions: ARCHITECTURE §1 Runtime topology. Bounded-helper allowlist: `test_process_custody.py`.

**Daemon stop.** `OwnedClaudexorDaemon.stop_outcome` (Panic, Restart) separates authenticated cooperative shutdown from forced signals (ARCHITECTURE §9). Read-only resolution never provisions a runtime/daemon, probes accounts or inherits another home's socket override. Stop uses the existing Node (`resolve_cli_command(require_npm=False)`), including Windows/bundled installs. RPC ack or lease release proves no physical exit; error codes grant no signal. Bound the manager lock; keep preparation/network/exit waits outside. Bounds: `CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC`, `CLAUDEXOR_STOP_EXIT_WAIT_SEC` (`runtime_limits`).

**Failed start.** Only `ExitFact.failed_without_control` latches daemon spawning. `claudexor_startup_failure.py` diagnoses the child log, never sets policy. Harvest under the reap lock at spawn/attach/stop (`_settle_exited_child`); release through sweep, Refresh, live attach or a new manager. No backoff/counter/cooldown, host heap sizing, writer-lease policy or third retrier; `NODE_OPTIONS` stays available. Settlement alone cannot retire: `still_continuable` keeps open/unknown owner lines and Continue; review/persistent lifetimes stay separate. Under the retirement lock, a complete second custody read proving no unsettled project run lets typed `project_has_threads` discharge `PROJECT_RETIRE_FAILED` as `PROJECT_RETIRED {project_kept:true}`; other outcomes stay retryable. Body collection follows this and owns jobs until exit without delaying Panic (ARCHITECTURE §6/§9).

**Platforms.** Close and forced worker/server/stray cleanup spare the shared daemon subtree. Skill-companion reserved-port/service ancestry rules stay scoped; another port grants no kill authority. Re-prove recorded servers' birth/command identity before signalling. Windows birth, command, Job, restart-handle and prior-generation stops need native evidence; portable fixtures prove none (psutil: Windows-only; frozen imports: packaging proof). ARCHITECTURE §1 "Platform substrate".

**Restart and Panic.** Separate stop from next-start selection; never hot-swap a pin. Planned restart stops the daemon only for a changed pin (`server_restart._stop_owned_daemon_for_new_pin`, after worker custody, before optional cleanup); never a veto (`test_planned_restart_engine_pin.py`); quiescence checks all members before releasing a writer fence (`test_process_custody_liveness.py`). Manual Restart's update gate and `safe_restart` refuse before stopping; `_stop_owned_work` follows durable no-resume flags. Reuse `request_cancel`, `kill_workers(reconcile_delegate_custody=False)`, `reconcile_orphaned_runs` over `read_owned_gateway` and `stop_outcome`; never ensure a gateway from cancel to daemon stop or infer stop outcomes from private manager errors. Unconfirmed steps keep custody and critical diagnostics, never defer or veto Restart; add no state, drain, lease or event kind: startup sweep recovers (`test_manual_restart_execution.py`). Panic is irrevocable: failed ingress start calls the executor synchronously; manager/diagnostic faults spare other requests; bounded writes precede final exit (`test_server_control_panic_daemon.py`). Test all four continuations in `test_planned_delegate_assignment.py`: S1 saved-work/queue returns bind the successor; undispatched owner-wait/planned carriers keep their own gates without interprocess once claims.

Extension HTTP responses run in the child: the runner owns staging, registration and cleanup; `extension_route_stream` owns pipe frames and ASGI delivery; spawn, registration, pipe shutdown and termination stay off the ASGI loop; cancellation binds to the loaded bundle before spawn; no total or pre-header deadline applies (ARCHITECTURE §3).

**Test runs.** Use `ProcessContainer(lifeline=True, overload=True)`: a POSIX pipe guardian survives owner death; Windows uses its kill-on-close Job. Reap before release. `config.TEST_*` and `test_parallelism.py` own physical budgets; nested runners default to one slot. `overload_stop` names the largest member and ends red, only past the admitted floor under the reserve or macOS kernel pressure; unreadable samples skip it loudly. No OS quota: summed RSS, detached members found by token every 5 s; token-dropping children and simultaneous guardian death are residuals. Fault matrix: `test_process_owner.py`.
