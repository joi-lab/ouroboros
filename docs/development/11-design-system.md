# Design System

This chapter preserves `docs/DESIGN.md` semantics in code: value and control ownership, review debt, history and viewport mutations, and visual verification. Rules name their tests/review items against missing tokens, overflow and bypassed primitives.

`web/ui.css` owns shared values and field, button, status and popup recipes; `web/index.html` and `web/onboarding_template.html` load it before page styles. `web/style.css` and page sheets own composition on the DESIGN bible's roles (registry: ARCHITECTURE §3 "Navigation and shared UI contracts"). Docs keep roles and failure-prevention rules, not values.

### Tokens and primitives

- **Shared control classes** (`.ui-control`, `.ui-checkbox`, `.ui-field`, `.ui-field-help`) are selected on the controls themselves, never through a growing list of page ancestors. A family migration removes the replaced chrome in the same change; domain drafts, validation and serializers stay with their owners. Review-only under CHECKLISTS item 26 (`web_design_system`); migrated consumers are pinned individually (`web/tests/ui_primitives.test.js`). DESIGN §8 lists the migrated families.
- **`web/modules/ui_primitives.js`** is the one safe-field renderer, collector, attribute escaper and tone/status source; `ui_helpers.js` and `utils.js` keep the re-exports. Keep the leaf free of shell, network and document-global initialization, so first-party and author consumers share one implementation (`web/tests/ui_primitives.test.js`).
- **Typography on a migrated surface** names a `--type-*` size token and a named foreground token in every text declaration: a size with no colour made secondary text inherit near-white primary ink. `tests/test_web_typography_static.py` keeps the class closed on the migrated families; extending that guard and migrating its subject are one commit (DESIGN §8 names the boundary).
- **The variable contract** is checked by the same test: every `var(--x)` resolves against its document's loaded sheets, and every `:root` token has a reader. Otherwise silent fallbacks or literals replace shared values. Neither page shadows a shared palette name; fix dangling names with existing tokens.
- **Appearance is client-local.** The choice and its radiogroup live in `web/theme.js`, outside Settings' `s-` input collector; theme-dependent images and selected warning controls use semantic tokens, never a raw hue. Every theme subscription has an owner and a disposer; `onTheme` is opt-in and resolved-only (storage, chart, Mermaid and iframe mechanics: ARCHITECTURE §3 "Navigation and shared UI contracts"). Request persistent desktop storage at every `webview.start`; verify a rebuilt launcher by quit and relaunch, not a server restart. Windows tints each window's caption from its top-level page's bridge call (`launcher_appearance.py`); macOS reads each document's title-bar declaration (`launcher_window_chrome.py`): no second theme store, frameless window, page-colour caption or unmeasured spacer. Regressions: `theme.test.js`, `test_appearance_static.py`, `test_launcher_appearance.py`, `test_theme_browser.py` and the `window_chrome` tests.
- **One semantic button variant expresses one action role**: neutral Settings and onboarding controls use `.btn.btn-default`; a one-action result row uses the `.settings-action-row` contract (status first, action docked right); notifications use the shared toast host. Working, warning, error and destructive states keep one meaning across Chat, Logs, Settings and Skills. Enforced by `web/tests/settings_action_row.test.js`; the toast-host and cross-page meaning clauses are review-only (CHECKLISTS item 26).

### Layout and containment

- **Layout and controls.** Top-level pages use a fixed `renderPageHeader` outside an independently scrolling body; primary actions, Refresh included, live in its `actionsHtml` slot. The shared tab strip (`renderTabStrip` + `bindTabStrip`, `page_header.js`) owns selection, ARIA and focus; callbacks own loading and panels. Dispose the binder with its page. Segmented single-selects use `renderSegmentedField`: columns follow its count, never per-control overrides; focus is the one ring apart from hover (`web/tests/segmented_field.test.js`; every group on the real page in Chromium and WebKit: `tests/test_segmented_layout_browser.py`). The navigation column's Projects list is its only scroller between pinned zones; a too-short window scrolls it whole, head sticky (DESIGN §10). Scroll bodies use `.scroll-fade-y`, except lists with rows shorter than `--scroll-fade-edge` and the crisp-edged Widgets board (DESIGN). Masonry packs through `web/modules/masonry.js::applyMasonry`, writing only `--masonry-*` custom properties (CSS Grid row packing leaves gaps under shorter cards); never move `<article>` nodes to reorder or resize, because a moved `<iframe>` reloads (persistence: ARCHITECTURE §3 "Widgets page"). A new visual dimension becomes a CSS variable consumed by shared classes; new inline `style=""` markup and `.style.<property>` assignments are review debt, except a measured value or a renderer's count of what it rendered (`renderSegmentedField` writes `--segment-count`) into a narrowly named custom property.
- **Containment.** A control never widens its column. Horizontal overflow lives in the wrapper that owns the wide content and declares `overflow-x: auto` (code block, `.md-table-wrap`, tab strip, Costs table cells), never in a page scroll body, whose `overflow-y: auto` alone makes `overflow-x` compute to `auto`. The shared `select.ui-control` recipe clips its own value (WebKit computes `overflow: visible` on a native select, which would become scrollable overflow of the page scroller). A grid track holding controls takes a minimum that yields to its container (`minmax(0, …)` or `repeat(auto-fit, minmax(min(100%, Npx), 1fr))`); a fixed px minimum rescued only by a viewport media query is review debt, because the viewport does not know the content column's width. The global webkit scrollbar recipe sizes both axes. Enforced by `tests/test_web_typography_static.py`, `tests/test_ui_settings_overflow_browser.py` (WebKit) and `tests/test_ui_settings_grid_tracks_browser.py` (Chromium).

### Chat surfaces

- **One owner intent has one control, built in one module** (DESIGN "References and actions"). `project_reference.js` alone builds Project references and raises `ouro:open-project`; callers choose layout, never label/class. `ui_helpers.createSystemMessageActions` wraps it under System rows and mirrored answers, `routing_receipt.js` ends the owner's receipt line with it, `work_portal.js` makes a bound card's footer; each composition owns spacing and focus clearance, never a global button margin. After control-text changes run `python scripts/regenerate_inventories.py` and compare adjacent `docs/inventories/UI_CONTROL_TEXT_INVENTORY.md` rows: reused primitives do not prove agreement, and a repeated intent gets one door first. Enforcement: `web/tests/project_reference.test.js`, `tests/test_project_work_card_browser.py`, inventory byte identity; "same intent" stays review-only (CHECKLISTS item 26).
- **Main decisions** follow DESIGN "Project question mirror": each `project_question_pointer` mounts one `chat_decision.buildQuizCard` copy plus Project reference at its ask time, never a second reduced form; the `current_questions` census only confirms or settles copies. `main_waiting.js` owns the amber pill and owner-wait System messages. Answer, close and dismiss share one decision ingress. Lifecycle words live once in `question_presentation.js` and `project_dialogue.QUESTION_STATUS`; a new state lands on both with its `question_presentation_parity.json` row in one commit. Settled cards leave through `releaseMessageNode` in the stable-viewport transaction (ARCHITECTURE §3 "Main rows and host-stamped card rows"). Waits come from owner-stamped `requires_owner_action`; Resume reads `work_stop.current_stop/stop_presentation`; technical refusals stay on the continuation (`continuation_refusal`); automatic waits stay quiet. Tests: `test_main_decisions`, `test_main_question_lifecycle`, `web/tests/main_decisions.test.js`, `web/tests/question_mirrors.test.js` and real Chromium/WebKit journeys.
- **The chat reader** (`document_reader.js`; DESIGN "Document reading") uses inline/artifact bytes, current owner-upload bytes (no rehash), or the tile's image source. Text errors explain known refusals; URL image errors offer Retry even for 404 (HTTP reasons are hidden). Markdown uses `mountChatMarkdown(…, { softBreaks: true })`. Close aborts reads/loads and prevents late paint; name, size and text use `data-i18n-authored`. Tests: `web/tests/document_reader.test.js`, `tests/test_ui_document_reader_browser.py`.
- **Project outcomes** keep managed/transferred-direct eligibility; Project-native replies and quiet runs stay local. `completion_answer` is an assistant `addMessage`; only `project_answer.js::decorateProjectRow` adds the CSS fold and Project reference, plus `completion_reason` beside nonclean finals. Full answers/documents open in Project, not Main expansion/Files. Task-card Files and quiz readers stay; availability never claims delivery. Publication addresses precede exposure and survive conversion; strict append precedes ACK; canonical receipts outlive bounded retry caches. Tests: `tests/test_project_completion_mirror.py`, `tests/test_quiz_delivery_recovery.py`, `tests/test_main_terminal_delivery.py`, `web/tests/chat_plain_system_rows.test.js` and real Main→Project fold/reader/download journeys.
- **A list editor** reveals a new entry, or after Remove its successor, through `ui_helpers.revealNewRow(row, field)` (scrolled into view, caret in its first field) and shows no error before a save attempt. A mark or switch patches its entry in place; open disclosures, keyed by stable UI key, survive repaint and reload (DESIGN §6). Tests: `tests/test_available_subagents_ui_static.py` (seam); `tests/test_ui_smoke_agents_panel.py` and `tests/test_subagent_card_quiet_browser.py` (behaviour; pointer and keyboard apart: a WebKit click need not focus).
- **Authorship:** follow DESIGN's chat-voice rule on backend and frontend alike (CHECKLISTS item 26). `tests/test_host_message_voice.py` pins the AST boundary; `tests/test_progress_narration_voice.py` pins live/history parity.
- **A host fact about a task is a row of that task's card**, never a standalone bubble beside it: the producer stamps the placement (`card_row` with `card_row_id`) and the browser attaches the row through one helper shared by live delivery and replay, falling back to a standalone System row only when the task has no card in the page (mechanism: ARCHITECTURE §3 "Main rows and host-stamped card rows"). A host fact that belongs in the card but carries no placement fact is review debt (CHECKLISTS item 26). A client-side list of row types is not the rule (DEVELOPMENT "Anti-pattern: an open default behind a closed exception list").
- **Task outcome truth** stays in `log_events.js::taskOutcomeSeverity` and `taskTerminalPhase`; `taskPresentation` is the one compact projection for chips, live completion, replay and child cards. Its host mirror is `project_dialogue.outcome_phase`, pinned to the browser by `web/tests/fixtures/outcome_phase_parity.json`: a new axis, reason or decision status lands on both sides in one commit, with a row there. The detail line comes from `taskReasonDetail` alone (ARCHITECTURE §3 "Task cards, errors and reason lines"); a non-terminal diagnostic never promotes the whole task, and an unknown event name never acquires Chat severity from keyword matching (BIBLE P5). Header liveness comes only from `/api/state`'s work projection, never a WS frame (a typing frame is a submission receipt); a failed task status synthesizes no header attention, toast or unread state (ARCHITECTURE §3 "Liveness census and the chat header"; `web/tests/chat_header_census.test.js`).
- **Narration leads; routine execution evidence stays compact; exceptions keep their explanation and controls** (semantics: DESIGN "Conversation activity block"; mechanism: ARCHITECTURE §3 "Direct turns and the activity block"). A note is promoted on the typed `narration` fact its producer stamps, never on a client reading of its text; execution evidence is one bounded row per block, never per event; host snapshots of the same turn merge field-wise (an absent field is unknown, not zero). A change to the block is shown at a realistic multi-call burst, collapsed and expanded, before acceptance. Enforced by `web/tests/chat_activity_block.test.js` and `tests/test_progress_narration_voice.py`.
- **Executor presentation and model-call provenance** consume the existing task and run-attempt facts (shape and producer: ARCHITECTURE §3 "Child cards and executor presentation"). Keep `executor_observation` event-local, never filled from a final-attempt model or progress prose; keep `execution_evidence` and `actual_substrate` terminal-only, with no new poller or execution-state store; `harness_presentation.js::executorIdentityMarkup` is the one label builder. The task's last usable solve response stays separate from initial routing, executor observations and final-answer authorship and survives result storage, copy-back, history rendering and every post-task or cost-only update; fan-out counters describe emissions and wall-clock intervals, never inferred execution waves. Tests: `tests/test_executor_observation.py`, `tests/test_task_model_execution.py`, `web/tests/task_result_reconciliation.test.js`.
- **Chat viewport invariant.** Sample live-edge intent before an ordinary transcript mutation; native scroll anchoring is not proof that the owner's visible message stays stable, so focused regressions disable it. The stable-viewport seam (ARCHITECTURE §3 "Timeline ownership and ordering") decides when the transcript follows the bottom; otherwise preserve the visible keyed message, nested card or Reviews anchor, and route late DOM writes through that seam. Main and Project transcripts reserve their overlaid composer with one non-shrinking flex spacer, because bottom padding can fall outside native WKWebView's scrollable overflow; the keyboard-in-flow layout removes that item.
- **History pages and reconnect** merge into the existing keyed card and row owners (mechanism: ARCHITECTURE §3 "Timeline ownership and ordering" and "History reads and the SSE v2 transport"). Preserve the actual selected, focused and expanded nodes (rebuilding an equivalent node is not preservation); a historical frame never grants current activity or replaces newer terminal evidence. Pages count the room's own rows, `has_more` follows the conversation, and completeness follows delivered physical spans, never dates, shared IDs or EOF. One wrapping Main/Project header note carries uncertainty, errors and approximate positioning (navigation clears approximation); initial loading and the beginning marker stay in the feed, without a duplicate header loading note. Tests: `web/tests/chat_history_integration.test.js`, `tests/test_history_room_pages.py`, `web/tests/chat_history_loading.test.js`.
- **Room work status** (`room_work.js`, `work_status.js`; DESIGN "Room work status") paints the server room's word and mark and one row per work, plus pending sends, unconfirmed cards: words from `task_phase_chip.js`, the work's controls via `work_status.openWorkControls`, questions via `chat_decision.revealQuestion`, navigation via the reading owner. It derives no status, mark, control or routing and adds no card tree, poller, store or word ranking.

### Responsive and accessible behavior

Navigation, headers, controls and dialogs stay operable by pointer and keyboard, keep focus order, and fit the relevant narrow viewport without stealing usable text space; use the shared responsive component before adding a page-specific layout. Engines and viewports follow risk. Containment is the WebKit-sensitive exception (a native select is not clipped there), so a change to a control recipe or a page scroll body is verified on the engine that shows the class: Playwright WebKit for native-control clipping, Chromium for engine-independent track geometry, measuring overflow on the scroll body's `scrollWidth`, not `documentElement`. Review-only: vision evidence and scoring per CHECKLISTS items 11(i) and 26 (`web_design_system`).

### Browser dialogs

`window.prompt`, `window.confirm` and `window.alert` are forbidden in `web/modules`; use `confirm_dialog.js::openConfirmDialog` (why, and its mode contract: ARCHITECTURE §3 "Navigation and shared UI contracts"). A critical action tests the exact confirmed result and keeps the confirmation and its side effect in one injectable flow. `tests/test_web_dialogs_static.py` keeps the native-dialog class closed.

`ui_interactions.js` owns focus, menus, popup geometry and message-field keys. Callers mount `.ui-popup` outside clipping, keep domain result/cancel contracts, dispose before removal and close menus before opening dialogs. Message fields bind `bindEnterSubmit` to their Send button: no second submit path or global textarea handler, and field-local listeners die with their nodes (DESIGN §3). `web/tests/ui_interactions.test.js` pins keys, focus, geometry and cleanup; `tests/test_ui_quiz_comment_only_browser.py` drives the real fields.

### Declarative widgets

A module handler that calls `OuroborosWidget.openExternal(url)` or `window.open(url)` from an anchor click also calls `event.preventDefault()`, invoking the helper during the gesture, before awaiting other work; automatic relaying respects an already-handled click.

`web/modules/widgets.js` hosts reviewed widget declarations (component families, author schema and limits: `docs/CREATING_SKILLS.md`; render modes, frame CSP and bridge: ARCHITECTURE §3 "Widgets page", "Declarative widgets" and "Module widget bridge"). A host editor keeps: nested interactive components use stable identity and one disposer; `subscription.render` is transitively passive; data updates patch the existing nodes at the mount's identity seam; passwords stay only in their mounted control, never in the retained form-value snapshot; forms, actions and jobs own their pending/result/error feedback by component id; text and attributes are escaped for their sink, media is constrained to extension routes or safe data URLs, charts stay readable through a semantic table; `kind: "module"` UI runs only in the sandboxed opaque-origin iframe; a failed list read exposes a contextual Retry through the keyed list reconciliation, never a global refresh or remount; every timer, listener, observer, stream, chart and mounted widget has a paired disposer.

Enforcement: `tests/test_widgets_ui_static.py` at commit tier; in the release-tier `ui_browser` lane `tests/test_widgets_ui_browser.py`, `tests/test_widgets_ui_browser_lifecycle.py`, `tests/test_widgets_ui_browser_patch.py`, `tests/test_widgets_ui_browser_widths.py` and `tests/test_widgets_ui_browser_capabilities.py`, all five before a release that touched Widgets; `tests/test_widgets_ui_browser_identity.py` also pins retained interactive nodes, password lifetime, local action feedback and non-destructive list Retry through real declarative consumers.

### Optional author controls

`ouroboros.server_web.read_author_kit_assets(request.app.state.repo_dir)` reads the fixed installed `web/ui.css` and `web/modules/ui_primitives.js` for an author-owned page (what the kit is and is not: ARCHITECTURE §3 "Author UI kit"). Resolve at the page or kit GET that serves a new mount, not at extension registration; the helper gets no bundle cache, new endpoint or auth exception. `docs/examples/author_ui_kit/` holds the two ordinary extension recipes; the kit stays optional and author-overridable, with no theme poller or forced remount. `tests/test_author_ui_kit.py` and `tests/test_author_ui_kit_browser.py` cover source-root delivery and real framed consumers, not an arbitrary author's CSP or application.
