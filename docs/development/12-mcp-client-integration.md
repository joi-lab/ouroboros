# MCP Client Integration

MCP is client-only; remote data is not policy. Owners select Settings references.

`mcp_catalog.py` owns atomic, stat-cached `_schema_version: 1` envelopes at `config.DATA_DIR/state/mcp/catalogs/server-<canonical_id>.json` (call-time root, Windows-safe prefix). Fields: `server_id`, `identity` (SHA-256 of listing configuration with credentials/resolved environment), `listed_at`, `complete`, ordered `items`, `latest_attempt {at, ok, error, partial}`. Exclude enablement, allowlists and runtime mode from identity. Items: name, description, input_schema, annotations, metadata; redact known secrets in descriptions/schema titles with `_redact_error_text`, never executable names/keys/enums/defaults. No disk wrapping/cuts; `normalize_listing` presents items; `_adopt_catalog` processes live and loaded items.

List at boot, MCP-fingerprint changes (Save/mtime) and Refresh. Configure seeds; reads adopt files without changing resident request arrays. Serialize each server without holding the manager lock over network waits; configuration events coalesce another background pass. Complete success (empty too) replaces evidence. Failure updates only the attempt; partial success cannot replace complete evidence. First failure is attempt-only; stale results write nothing. Failed publication keeps local tools and reports `publication_error`, never `published`. Only server config events prune (`test_mcp_catalog.py`).

HTTP/SSE validate URLs/headers, refusing cross-origin credential redirects. Settings masks literal headers; echoes stay visible. SDK logs redact tokens/selected secrets, not header values. Import/Test never publish; prove transports with loopback servers (`tests/test_mcp_*.py`).

Stdio uses exact argv, cwd and selected env. After admission, `workspace_executor.resolve_process_env` resolves references under `tools/process_facts.py::settings_environment_allowed`: root/Cyber acting, not Presence; MCP/skill grants add no reference authority. Mask secret diagnostics/logs; keep secrets out of host argv, shell source and process ledgers; Docker uses inert aliases. Services overlay a minimal baseline; commands/scripts/verification inherit theirs. Tests: `test_process_environment.py`, `test_workspace_executor_services.py`.
