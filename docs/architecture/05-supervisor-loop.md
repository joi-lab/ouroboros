# 5. Supervisor Loop

`server.py::_run_supervisor()` owns the pooled scheduling tick and lifecycle lock. Cancellation intent precedes teardown. Its admission, waits, controls and maintenance keep intent, outcome and money separate; unknown is not zero or absence.

### Tick and locks

`state.init_state` alone creates state on first-boot proof, before bridge publication (PERSISTENCE.md). Each tick publishes liveness, rotates logs, checks workers, drains bounded control before telemetry, which never delays an answer (`runtime_limits.py`; `event_taxonomy.EventDisposition.lane`), takes bridge input (a backlog skips its wait and idle sleep, not intake), projects money, enforces deadlines, runs maintenance, admits/assigns, snapshots, publishes direct roots, ticks consciousness and writes a busy minute's `supervisor_load` row (`publish_supervisor_load`, `supervisor/loop_load.py`). Three consecutive tick crashes clear readiness and notify the owner, shutdown excepted (`_SignalStopServer`, §9).

`supervisor/event_observation.py` indexes pending idle inputs across both lanes and holds the outstanding-delivery membership (`put_unless_outstanding`); `event_taxonomy.py` names the reducers changing idle inputs. Pending inputs defer only idle grace/reaping, granting no progress or lease; heartbeats, telemetry and host narration cannot indefinitely spare a hung task; dequeue does not certify a failed handler's effects.

`state.json` money is display, not admission (§10.28): totals persist, `usage_projection` owns per-root values, `usage_writer_snapshot` renders once per dirty tick after intake. Ledger `(compaction_epoch, seq)` ordering rejects stale renders. Quarantine (`integrity_degraded`) freezes display until explicit repair; failed writes stay dirty until `BUDGET_PROJECTION_RETRY_SEC`. The async OpenRouter comparison never changes admission.

`supervisor.queue._queue_lock` (Q) owns queue transitions; `task_admission` reserves identity before effects (§1). Admission persists nothing under Q: child receipts, launch marks and warm Resumes reserve memory there, persist on the generation's admission lane (`PreparationGeneration.wait_store`: a slice per attempt, controls re-read between, never behind a copy), re-take Q, compare memory, then put; a later refusal settles the row typed; an uncertain write is inspected, never re-sent. Closed, it starts nothing; paused, no launch, yet committed marks reach a worker: process-ending stops pause it and wait before reading the queue or writing restrictions (`pause_admission`); a longer stall, a refusal or error after its marks, or Panic leaves one possibly dispatched. Assignment skips registered inline ids, reaping, holds, claimed launches, closed projects, competing writers and exhausted root capacity. Cold external holders keep their project lane (§6); capacity counts idle assignable workers. Remaining outer-lock probes use `store.acquisition_budget(0)`: confirmed contention defers unsent work off locks, unknown grants nothing. Only Evolution has mode fences. `execution_owner.kind` governs carrier policy and pooled completion notifications; `_is_direct_chat` is historical. First `detached_at`/`detached_by` survive queue/result metadata.

### Admission and addressing

Headless addressing is fixed at admission (`log_addressing.ingress_chat_id`). A registered Project's explicit `chat_id` must match its thread; any other address, hidden included, gets a typed 400, so a Main card never detaches from its Project work. Without a Project, API tasks default to `HIDDEN_CHAT_ID` (0). Confirmed browser Publish requests Main with `source="web"`/`WEB_UI_CHAT_ID` (caller-declared addressing, not authentication); other non-Project addresses are refused. Active registered Projects admit work into their thread. Main gets one host-stamped completion only for work addressed or bound there; other work stays in the hidden partition, silent in chats, readable via terminal, `--result-json-out`, Logs and `GET /api/tasks/<id>`. Reserved inactive Projects keep their chat valid for the queue's typed lifecycle refusal.

Admission names runs without model calls; `task_named` never uses status as a title. Authored `title` (`ouroboros run --title`/top-level contract) fills `title`/`suggested_name`; `metadata.title`/`metadata.project_id` get 400. First-line fallback fills only `suggested_name`, keeping later names. Model `start_task` needs a root title for separate new work. Owner/API/queued events keep fallback; historical routing cards resolve.

`queue_snapshot.py` publishes changed snapshot/dispatch/direct-root generations under Q; `queue.alive` fences restore. Empty processes/concurrent restore preserve unread work; Continue waits (`queue_not_restored`). `queue_observation.py` keeps missing/mismatched evidence UNKNOWN; contended unsent probes retry outside money locks. Restore fences interrupted RUNNING/direct roots except saved work without Stop (§6), and cancels their pending children. `budget_resume.newer_continuation_basis` re-decides spent Resume carriers and marker-less stale-grant holds: an owner wait, exact planned handoff, working recovery or live exact pause keeps custody; confirmed absence fences the work; unknown keeps the hold, which owns the spent grant's identity and no owner/model selection releases. Formats: PERSISTENCE.md. Scratchpad return needs `pending_restart_verify.json`.

`_claim_worker_launch` reserves the row and the slot under Q; the lane reads the schedule control, then puts only after the dispatch marks commit in one write, before anything says `possible` (`_commit_launch`); snapshots never replay a put. Contention is demand, not refusal: the lane retries the same row, attempt and marks; a refusal frees the slot, the row stays demand. Dispatch, hold release and deadline expiry read the loop's `governing_continuation`; saved successors need the frozen source and prior `admitted_dispatch_attempt` (§6). Proven no-put callers bind source/attempt/claim to terminalization, rechecked by the reaper; terminal rows stay terminal; accepted/sealed roots' descendants remain fenced except exact pauses. `task_status.execution_observation` keeps fresh activity apart from lifecycle; only pooled work admits worker-boot orphan inference.

`supervisor/workspace_preparation.py` owns child admission off the event thread: the loop claims a request in memory, never re-putting it; copies run on the copy lane with preparation-time bytes, admissions on the admission lane (readonly children whole; each claim's receipt, then its put after memory-only rechecks). Neither direct-child-count pre-check (the worker's `schedule_subagent`, the supervisor's early check) refuses an unknown count; the interlocked re-check decides (`control_delegation.schedule_delegation_refusal`). Startup and the reconcile pass settle proved preparation-only loss as never admitted (each case: `recover_interrupted_preparations`) and keep custody for uncertain admission (§10 invariant 19). `forward_to_worker` also reaches a requested child's mailbox. Entry: `events_schedule_task`, `task_admission`.

### Schedules and follow-ups

`supervisor/queue_schedules.py` alone writes `state/scheduled_tasks.json`, every mutation inside `schedule_transaction` (Q, then the sidecar lock). `load_schedule_store` reads only absence as empty; an unreadable table raises `ScheduleStoreUnreadable`: no mutation, unknown reads.

`schedule_occurrence.py` admits at most one root per due occurrence, enqueued with a frozen receipt; a typed `hold` is a wait, not a failed root; the same token and task id re-prepare after restart, and restore follows the receipt (positive `possible` held, a proven-unsent first attempt unsent, unreadable or foreign results and receipt-less admissions unknown). Edits/disable govern only unstarted work; deletion returns `delete_deferred` for owed or unknown work. A waiting cron row keeps one overdue occurrence, then advances. A `kind:"notify"` row is a note, not an occurrence: the pass consumes it and `schedule_notes.py` shows the mind's words as one signed `reminder` System row; an unconfirmed show becomes `last_error`, never retried.

`followup_policy.py` binds explicit related/independent relationships; host provenance (`continuation_of`, origin) grants neither relationship nor billing authority; related work keeps its origin's group cap, source and deadline. Lifecycle controls govern future work; missing, unreadable or stale queue evidence keeps work held; Restart and Stop persist restrictions before marker consumption; a Stop's `followup_stop` lands on the original result even if completion wins. `stop_action_id` names the ingress action apart from custody `request_id` (exact retries rejoin, altered arguments refuse, omitted ids claim no replay). Restore with `expected_hold_id` releases only that hold; generic Restore can re-enable a schedule and cancel pending deletion. `schedule_mutation` intent/outcome rows share one `operation_id`; an outcome failure reports `changed_audit_incomplete` without unaudited rollback. `manage_schedules` and `POST /api/schedules/{id}/action` share this seam with explicit action/reason, no text inference (owner edits: `supervisor/schedule_lifecycle.py`). Scans skip disabled idle rows and observe policy off Q; publication compares the row and Restart generation. Occurrences/deletes still reconcile. Final enqueue, worker put and note consumption recheck controls under their locks.

### Completion, owner waits and restarts

Pooled completion separates a file-save attempt from publishable terminal truth: workers prepare terminal files (`headless.prepare_terminal_task_files`) before `task_done`; the host publishes only once `headless.terminal_task_files_ready` confirms them current; unpublishable completions stay RUNNING under `enqueue_terminal_file_recovery` on the health cadence (never a false Done or replayed model work). Only confirmed absence of a terminal source reaches the lifecycle-fault owner, marking execution `infra_failed`; the authored answer, review and cost survive.

Answer first: `agent_task_pipeline.emit_task_results` owes and live-enqueues the root final BEFORE cost reconstruction, review evidence/input capture and `_store_task_result`; `task_done` follows that store. Carrier ordering and `task_finalization_timing` (`basis: post_answer_store`): `finalization_timing.emit_post_answer_timing` docstrings. Timeout/dead-worker recovery adopts owed, exhausted, delivered or unreadable registrations; direct boot-fence custody requires a readable registration (`working_checkpoint.adopt_registered_answer`). Adoption preserves the answer with `failed`/`infra_failed`/`finalization_incomplete` and a host notice, never replays the prompt.

`worker_owner_wait` keeps task, worker and browser RUNNING; durable parking lends capacity; a Resume's grant persists on the admission lane under its claim, rolled back when the stack changed before the put. Contention retries the same row under Stop/deadline/ceiling. Pre-ACK sleep and the native-restart interval fold once. Resume keeps the attempt, never replays. Main/Project waits survive planned restart with unread input; mail wakes, only owner answers answer. Settled Project post-work rejects steering (`owner_mailbox.mailbox_drain_ended`). Direct waits (`owner_wait.direct_owner_wait`) lend no pooled slot or cold restart.

Crashes, timeouts, restart and update-abort returns follow §6 Saved working state, not OS browser sessions. A retained wait dominates rolling work only while its retaining pause is live (`working_checkpoint.live_park`); refused promised returns emit `restart_return_refused`. Updates prepare handoffs before pool stop (failure blocks update); Rollback prepares none. Cold continuation restores economics, rereads cost authority (`task_pacing.restore_cost_ceiling`), keeps deadlines/wait time.

### Cancellation

Cancellation is intent-then-custody (§10 invariants 14-15), intent and outcome separate fields:

1. **Intent.** Every cancel ingress (`cancel_task` tool, HTTP single/cascade, evolution stop, project deletion, cascade sweep, boot recovery of `cancel_requested` files) writes one durable row via `cancel_intents.request_cancel` into locked `state/cancel_intents.json`; a failed write tears nothing down (`CANCEL_INTENT_WRITE_FAILED`, HTTP 503). Owner evolution stop is sticky (`evolution_owner_stopped`) until an owner start clears it.
2. **Scope.** Recorded scope only widens (single to cascade; Stop-now cannot shrink a cascade). Reaping is no cancel ingress: its custody survives health hand-back until replay settles. Stop needs explicit intent; a replay in flight keeps it pending.
3. **Claim.** `task_lifecycle.cancel_task_custody`, the one settle owner, takes the exclusive claim (§10 invariant 14); racing custodies never double-settle; the `cancel_task` event only wakes the intent. A live direct-chat turn stops through the same custody (`worker_chat_lane.py` writes one typed `finalize_now`; its loop ends at the next round boundary, no further model call); Stop during post-task synthesis discloses skipped paid stages as `post_task_stop_reason`. A still-live turn releases the claim for the sweep, never publishing a fabricated `cancelled` row.
4. **Kill and re-check.** Custody confirms process death, then rereads the settled result; natural completion wins (§10).
5. **Reconcile, capture, settle.** Open delegated runs are re-audited from durable custody rows; workspace artifacts come from the real tree (a failed or unrunnable capture is `failed`, never `missing`); the result carries reconstructed-or-unknown cost, never a fabricated `$0`; only here is `parent_decision` stamped; `cancel_publication` keeps `cancel_origin`; restore-fence receipts name its cause. HTTP proves transport, not owner intent.
6. **Owe, then publish.** After claim re-check, owe the terminal answer before the terminal row, settled intent and `task_done`; pending-deadline expiry owes inside its lock too. Winning completion withdraws salvage; crash after settlement replays debt. Cascades send one root digest (`cascade:<root_tid>:<request_id>`). `terminal_projection.py` holds Done until no `final:`, `cancel:<tid>:<request_id>` or `cascade:` debt remains; unknown/exhausted delivery stays visible (`_delivery_disposition`, `events_chat_delivery._handoff_delivered_review`).
7. **Watchdog.** The tick's off-drain sweep (`server_maintenance.py`, `sweep_cancel_intents`) re-feeds unclaimed/abandoned intents to custody (cascades as cascades): a lost control event or custody dead mid-teardown cannot wedge cancellation.

Effective results show typed `cancel_state: "pending"` with `cancel_reason` until settlement (UI: §3 Stop and cancel controls). Steering writes (`tell_task`, mailbox follow-ups, `forward_to_worker`) are refused typed during a pending cancel; restore and pre-assignment read the projection under Q, so a cancelled pending task never starts. `task_done` asserts a settled outcome validated against the durable result (`events_task_done`); a mismatch is a lifecycle fault, left to custody while cancellation is pending.

`terminal_delivery.py` owns the outbox: exact-id debt before enqueue, boot/tick replay; refusal keeps debt (PERSISTENCE.md). Producers use the injected bus. Queued/already-delivered/queued-unregistered/unavailable remain distinct; queued/in-flight originals neither duplicate nor spend retries (`put_unless_outstanding`). Exhaustion/eviction retains payload and preserved copy until receipt. Card dedupe probes task/summary id/readiness token in `dialog.sqlite`; importing misses stay owed. Main's frozen event/clock survives eviction until strict receipt (§3). Cancel/non-retry reap sends lineage-routed unreviewed salvage; retryable reap sends nothing. Receipt proves neither display nor reading (§10).

Best-effort dialogue tries zero wait, publishing live at the same timestamp; `dialogue_retry` bounds rows/bytes, counts eviction (progress first) and exit loss, so crash or sustained contention can lose rows (PERSISTENCE.md). The delivery duty and workers drain it (before an append, at task end, exit or an idle probe; retiring it counts leftovers lost); content-address dedup covers an uncertain COMMIT without a second frame. Required rows and named inbound acceptances never use it; inbound failure stays loud.

Named sends keep timestamp and id; an unnamed notice stays with its retrying producer. The duty runs deferred append/send/receipt off the consumer: bus membership protects originals, process claims physical completion, persisted `emitted` facts replay only receipts, the bounded id cache covers busy registration (an earlier crash: at-least-once). Chat handlers write under a 0.25 s slice (progress: zero), other writers under their callers' waits; transport faults keep clocks/caps, busy storage spends no attempt, projection keeps indexed readiness.

### Stop policy and hurry

Stop policy is an axis on the same durable intent, independent of cascade scope. An omitted or empty-body cancellation is immediate (CLIENT_CONTRACT §8). `stop_policy=finalize_then_cancel` answers 202 with the intent open and runs one bounded finalization episode: descendants settle first, then the root's `finalize_now` allows at most one tool-less model turn, terminalizing under the honest owner reason (`supervisor/owner_stop.py` docstring). `OWNER_STOP_OUTER_CAP_SEC` bounds grace; explicit deadline and absolute ceiling stay independent. Transitions are monotonic (immediate hardens pending graceful; graceful never softens accepted immediate); Panic bypasses both.

Owner "hurry" is a typed task-local `kind=hurry` owner-mailbox control (`ouroboros/owner_hurry.py`; `gateway/task_hurry.py`): it makes that task's force-plan projection advisory; never a chat message, settings mutation or weakening of the P3 commit/review gates; attempt-scoped (`retry_reset` strips it on each same-id requeue).

### Event bus, timeouts and worker readiness

One server-owned, process-lifetime manager bus serves worker generations/direct actors (§Tick and locks). Respawn never rotates it; lookup cannot create it, producer exit cannot close it, and a killed producer cannot corrupt another feeder frame. `log_addressing.task_event_queue` stamps chat/lineage by value so late telemetry stays addressed. Workers attempt checkpoint storage before one live frame (`loop_messages._emit_checkpoint_event`); the nested handler persists only `task_start_settings_reload_failed`. `utils.append_jsonl` streams runtime `logs/*.jsonl` excluding dedicated-sender types (worker suppression types and the server superset): one live frame/event, one durable `llm_api_error`/failed call.

Heartbeat proves liveness; progress and model-usage events prove task advancement. Progress spares orchestrators' idle rail, never deadline, Stop, budget or execution ceiling (solving/finalization, not settled post-work; §6); `queue_timeouts` expires queued deadlines undispatched. Timeout freezes under Q, marks `reaping`, and delegates kill/join/salvage/retry/respawn to `task_reaper`; live descendants forbid blind orchestrator replay (a duplicate tree); unconfirmed death keeps the reservation, emits `task_reaper_wedged` with a Restart hint and permits no terminal/retry/replacement rather than race a live process. Typed incidents keep `TIMEOUT_TERMINAL_REASONS` identity.

One Python worker starts; more come on demand and quiet surplus is retired, with no idle timer (owner choice: idle memory beats burst startup); explicit counts and MAX stay. Startup verification runs once per server generation and code version (`state/startup_verification.json`; `worker_boot` stays per process); a worker caches bytecode in a prefix inside its data dir (`worker_process.write_bytecode_to_prefix_only`). `worker_assignment` forecasts residual demand with dispatch's chooser, claiming nothing; `worker_pool_lifecycle` grows only that deficit and keeps one ready spare at quiescence; `booting` slots forecast capacity, unresolved reservations stay charged.

Assignment/free counts require live current PID/birth-bound `worker_ready`: births are compared only when both sides measured one, else the pid (`_births_agree`, `_record_worker_processes`). SHA equality proves neither loaded code nor review. `worker_starting` grants one bounded extension (`runtime_limits.py`); watcher errors use bounded replace/park. Per-slot exhaustion leaves unused MAX headroom. All-spent capacity closes pooled ingress (`/review` too); `disable_exhausted_worker_pool` fails unstarted rows with a Restart hint, sparing chat, control, boot and update recovery.

Surplus retirement and cap-full warm Resume share a quiescence token probe; a worker answers once its local reviews, tool futures with late callbacks and abandoned senders settle (`worker_process.local_work_settled`; `review_operation._LIVE` counts `wait.close` and final pointer publication; unknown defers; no history scans). Retirement reserves the slot, kills with kept services through the off-loop `task_reaper` and frees capacity only on confirmed death; the lifecycle serializer guards membership, never a kill or join (`request_worker_quiescence`, `retire_quiescent_worker`, `reap_idle_worker` docstrings). No idle timer, rotation or setting; intentional retirement is not a crash.

`worker_health.recover_confirmed_dead_worker` reserves exact custody under Q for the reaper's `confirmed_dead_worker`: saved terminal bytes (`task_exception` after `handle_task` failure included) win over signal death, live exact pauses re-park (§6), unknown/incomplete publication stays `TerminalFileRecoveryPending`; only confirmed absence reaches crash policy, where eligible crashes retry within `QUEUE_MAX_RETRIES` and budget continuations forbid ordinary retry (storms: module docstring). After process custody, startup recovers addressed `pending_drives`, nonterminal/synthesis obligations and saved answers before orphan healing.

### Maintenance and custody

`server_maintenance.py` gives schedules, cancel, delivery, pause-notice, usage, post-task recovery, held Continues, custody and reconcile separate single-flight latches; domain claims/receipts, not pass order, arbitrate. Writer holds have no fence: held rows schedule their re-check. `bind_body_lifespan` starts after store publication; replacement joins closing jobs off-loop; cold holders enter orphan-exclusion before recovery (§6). Closure or a returning Stop admits nothing, a stop's pause no launch; none proves exit (§10.24). An `invalid_source` refusal retries only on a changed watched file, rows or release (`source_retention._unavailable_basis`, a durable job row); cost reads treat busy as no observation. Delegated sweeps leave review-owned invocations to panels (`delegate_terminal`); no-file captures mean no changes only after success (`delegate_directory.capture_directory_result`). Reaping checks PID/birth/command/task/generation, never command classes or another install. Watchdogs journal stalls, report wedged actors, suggest Restart, kill no thread.

History-sized work runs in one maintenance child (`python -m ouroboros.maintenance`: own group, low priority, Panic/exit census), never on a server thread; each job of `maintenance.JOBS` keeps durable `job:<name>` facts in `state/current.sqlite`. `maintenance.child.tick` (a reconcile pass's end, a first tick) only reserves the slot; the child spawns when a job's facts say work waits, not on a timer. Queue-owned recovery and drive settlement stay in the server. Each reconcile pass (300 s) runs age-only retirers; each custody pass (600 s) retires copies and old engine programs; Storage's free action (§3) reuses both.

Cooperative project checkpointing (`supervisor/events_coop_checkpoint.py`) runs on two equivalent quiescence triggers, a root settling without live descendants and the last child settling under an already-terminal root, because a root-scope budget stop terminalizes the root before its children. The bounded git chain revalidates quiescence under Q just before mutation. Only host-minted project roots qualify: owner-attached folders are never auto-committed, credential-shaped files stay excluded and disclosed; each material success, skip or error gets a durable receipt.

### Bridge intake and commands

Bridge intake retains identity, transport and durable acceptance; failed handlers requeue only their unprocessed memory tail, never accepted rows. Room input goes to its sole live reader, including a warm question wait, excluding queued/held work. Explicit tell owes mail without resuming. Answers try the reading asker, then proven admitted successors under each admission lock, then named fresh-head ingress at the saved publication address. Mail stays owed until saved-read acknowledgement. Panic has emergency ingress.

The bridge recognizes `/panic`, `/restart`, `/review`, `/evolve [on|off]`, `/bg [start|stop|status]` and `/status`; other text enters ordinary agent routing. External transports invoke them only with positive owner identity and a transport-specific owner-chat binding known current; unknown refuses and registers nobody; Panic keeps its positively observed immutable binding until owner Reset closes it (`PanicIngress`). Commands reuse runtime-mode, queue, cancellation and typed-result authority. Archive readers keep rotated runtime logs' timelines (§1).

Confirmed budget/owner pauses register `pause_notices` with the confirming result update (`pause_notices.py`): one obligation set, a saved System chat row as the receipt, a failed append still owed, older episodes retained by Resume and newer pauses. Consciousness reports paused/pausing or unknown, never guessing settlement.
